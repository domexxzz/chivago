# 80 — ขอข้อมูลจาก มทร.ธัญบุรี · ฟีดจริงตัวแรก

**จัดทำ:** 26 พฤศจิกายน 2569 ต่อจาก [#318](https://github.com/domexxzz/chivago/pull/318) และ [#319](https://github.com/domexxzz/chivago/pull/319)
**ส่งถึง:** ผู้ประสานงานฝั่ง มทร.ธัญบุรี เพื่อส่งต่อให้หน่วยที่ถือข้อมูลแต่ละชุด
**สถานะ:** ยังไม่ได้ส่ง ยังไม่มีข้อไหนได้คำตอบ

**สัญลักษณ์:** ✅ ตอบแล้ว ใช้ออกแบบได้ · ⚠️ ตอบแล้วแต่ยังไม่ยืนยัน · ❌ ยังไม่มีคำตอบ

> **เหตุผลที่มีเอกสารนี้:** ฝั่งโค้ดของสามเรื่องที่ทำไว้ให้ มทร. — ตลาดงานเกษตรแฟร์ สั่งอาหารล่วงหน้าที่โรงอาหารกลาง และรถในมหาวิทยาลัย — **เขียนเสร็จแล้วทั้งสามเรื่อง และทั้งสามเรื่องรอข้อมูลจริงอยู่** ไม่มีเรื่องไหนติดที่วิศวกรรม งานที่คุ้มที่สุดตอนนี้จึงไม่ใช่เขียนโค้ดเพิ่ม แต่คือได้ฟีดจริงมาหนึ่งชุดเพื่อพิสูจน์ว่าวงจรทำงาน
>
> เอกสารนี้เรียงจากสิ่งที่มหาวิทยาลัย**มีอยู่แล้ว**และส่งได้ทันที ไปหาสิ่งที่ต้องลงทุน ข้อ A1 กับหมวด B ไม่ต้องซื้ออะไรและไม่ต้องเขียนโค้ดฝั่งมหาวิทยาลัยเลยแม้แต่บรรทัดเดียว

---

## หมวด A รถมินิบัสในมหาวิทยาลัย

> ข้อ A1 คือข้อที่ปลดล็อกได้เร็วที่สุดในเอกสารนี้ ตอบได้ด้วยอีเมลฉบับเดียว

**A1. ตารางเดินรถฉบับไหนที่ใช้จริงอยู่ตอนนี้** ❌

- **เหตุผลที่ถาม:** อ่านหน้าเว็บของมหาวิทยาลัยเมื่อ 26 พฤศจิกายน 2569 พบสองฉบับที่ขัดกัน ฉบับหนึ่งระบุ 16 เที่ยวระหว่าง 06.55–17.35 อีกฉบับลงวันที่มิถุนายน 2567 ระบุสามสายพร้อมป้าย เดินรถ 06.30–21.00 ทั้งสองฉบับไม่ให้พิกัดป้าย และไม่มีใครยืนยันว่าฉบับไหนถือ
- **ผลตอนนี้:** แอป**ไม่แสดงเวลารถเลย** ขึ้นข้อความว่า *"มหาวิทยาลัยมีรถมินิบัสภายใน แอปยังไม่แสดงเวลา จนกว่ามหาวิทยาลัยจะยืนยันตาราง"* แล้วลิงก์ไป `rmutt.ac.th/bus-service-center/` เพราะเวลาที่เราเดาเองจะมีคนไปยืนรอที่ป้ายจริง
- **ที่ขอ:** ระบุว่าฉบับไหนถือ ถ้าทั้งสองฉบับเลิกใช้แล้วก็ขอฉบับที่ใช้จริง ในรูปไฟล์หรือข้อความก็ได้ ไม่ต้องเป็น API

**A2. พิกัดป้ายในมหาวิทยาลัย** ❌

- **เหตุผลที่ถาม:** ในแอปมีป้ายของสาย 538 สี่ป้ายที่ขอบมหาวิทยาลัย (อ่านจาก OpenStreetMap — ราชมงคล ประตู 3 กับอีกสามป้ายที่ไม่มีชื่อบนแผนที่) แต่**ป้ายของรถในมหาวิทยาลัยเองไม่มีอยู่ในฐานข้อมูลใดเลย** โครงสร้างข้อมูลฝั่งเรารับป้ายที่ไม่มีชื่อได้ แต่รับป้ายที่ไม่มีพิกัดไม่ได้ เพราะวาดลงแผนที่ไม่ได้
- **ที่ขอ:** ชื่อป้าย + พิกัด (ทศนิยม 5 ตำแหน่งขึ้นไป) ถ้าไม่มีเก็บไว้ **เราเดินจับพิกัดเองได้** ขอแค่เจ้าหน้าที่พาชี้ว่าป้ายจริงอยู่จุดไหน ครึ่งวันพอ
- ป้ายที่ไม่มีชื่อ ส่งมาเป็นพิกัดเปล่าได้ แอปจะเขียนว่า *"ป้ายที่ยังไม่มีชื่อบนแผนที่"* ไม่ตั้งชื่อให้เอง

**A3. รถมี GPS อยู่แล้วหรือไม่ และขอฟีดได้ไหม** ❌

- **เหตุผลที่ถาม:** ตอนนี้แอปตอบคำถาม "รถมาเมื่อไหร่" ด้วยการให้**คนกดแจ้งว่าเห็นรถ** แล้วบอกว่าเห็นครั้งล่าสุดเมื่อกี่นาทีที่แล้วและห่างกันเฉลี่ยเท่าไร ซึ่งเราเขียนให้เป็น *การสังเกต* ไม่ใช่ *ตาราง* ถ้ามี GPS จริงก็เลิกเดาได้ทันที
- **ที่ขอถ้ามี:** URL เดียวที่ตอบ JSON แบบนี้ เรียกด้วย GET

```json
{
  "ok": true,
  "data": {
    "observedAt": "2026-11-26T15:09:51+07:00",
    "vehicles": [
      {
        "vehicleId": "rmutt-van-03",
        "routeId": "rmutt-line-1",
        "lat": 14.035563,
        "lng": 100.724385,
        "observedAt": "2026-11-26T15:09:48+07:00",
        "nextStopId": "rmutt-gate3",
        "etaMin": 4
      }
    ]
  }
}
```

เงื่อนไขฝั่งเรา ตรงกับที่ใช้กับสั่งก่อนและสนามแบดอยู่แล้ว:

| ข้อ | ค่า |
|---|---|
| วิธีเรียก | GET ไม่ต้องมี CORS (เรียกจากเซิร์ฟเวอร์ถึงเซิร์ฟเวอร์) |
| การยืนยันตัวตน | ไม่ต้องมี หรือ token คงที่ตัวเดียวที่เราเก็บเป็น secret |
| ขนาดคำตอบ | ไม่เกิน 64 KB เกินกว่านั้นเราปฏิเสธโดยไม่อ่านต่อ |
| เวลาตอบ | ภายใน 2 วินาที |
| redirect | เราไม่ตาม |
| `observedAt` | **บังคับ** ทุกคัน ไม่มีเวลา = เราไม่แสดงตำแหน่ง |
| `etaMin` | ใส่ก็ได้ ไม่ใส่ก็ได้ — **ถ้าไม่ใส่ เราไม่คิดให้เอง** |

**A4. ใครเป็นผู้ยืนยันเมื่อตารางหรือเส้นทางเปลี่ยน** ❌

- ขอเป็น**ชื่อหน่วยงานหรือตำแหน่ง** ไม่ใช่ชื่อบุคคล เพื่อให้แอปอ้างที่มาได้ว่าใครรับรองตัวเลขนี้ และเพื่อให้รู้ว่าต้องถามใครเมื่อข้อมูลเก่า

## หมวด B รายชื่ออาคารและผังพื้น

> หมวดนี้**ไม่ต้องมีเซนเซอร์ ไม่ต้องมี API และไม่ต้องเขียนโค้ด** เป็นไฟล์ที่มหาวิทยาลัยมีอยู่แล้ว และเป็นคำตอบของคำถามที่นักศึกษาถามบ่อยที่สุด คือ *"ห้องนี้อยู่ตึกไหน ชั้นไหน"*

**B1. รายชื่ออาคาร** ❌

- **เหตุผลที่ถาม:** มทร.ธัญบุรีกว้าง 1.23 ตร.กม. (1,087 × 1,129 ม. วัดจากขอบเขตใน OpenStreetMap) แต่ในแอปมีแค่**ห้าสถานที่** — หอสมุด สวนราชมงคล โรงอาหารกลาง สนามกีฬา น้ำพุ ซึ่งเลือกมาตอนเปิดพื้นที่ให้ครบชั้นของเกม ไม่ใช่เลือกเพราะเป็นที่ที่คนต้องไป ไม่มีอาคารเรียนแม้แต่หลังเดียว
- **ที่ขอ:** ชื่ออาคาร · เลข/รหัสอาคาร · คณะหรือหน่วยที่ใช้ · พิกัดจุดเข้าหลัก หรือขอบอาคารถ้ามีเป็นไฟล์แผนที่
- รูปแบบอะไรก็ได้ที่อ่านด้วยเครื่องได้: CSV, Excel, GeoJSON, Shapefile หรือ KML

**B2. ผังพื้นแต่ละชั้น** ❌

- **เหตุผลที่ถาม:** ข้อมูลในอาคารไม่มีใน OpenStreetMap และเราจะไม่เดินสำรวจเอง — ต้องได้จากมหาวิทยาลัยเท่านั้น
- **ที่ขอ:** ไฟล์ผังพื้นต่อชั้น (PDF, DWG, หรือรูปก็ได้) พร้อมเลขห้องตามที่ใช้เรียกกันจริง
- ถ้าให้ได้แค่บางอาคารก็เริ่มได้ ขอเป็นอาคารเรียนที่คนเข้าออกมากที่สุดก่อนสามถึงห้าหลัง

**B3. เลขห้องใช้ระบบอะไร** ❌

- เช่น `ST-1203` อ่านว่าอะไร อาคาร ST ชั้น 12 ห้อง 03 หรือ ชั้น 1 ห้อง 203 — ถ้าตีความผิด แอปจะพาคนไปผิดชั้น

## หมวด C ที่จอดรถ

> คำถามอันดับหนึ่งของคนขับรถเข้ามหาวิทยาลัย และเป็นหมวดเดียวในเอกสารนี้ที่อาจต้องลงทุน

**C1. มีระบบที่นับรถเข้าออกได้อยู่แล้วหรือไม่** ❌

- ไม้กั้นที่นับจำนวน กล้องอ่านทะเบียน หรือระบบบัตรเข้าออก — ถ้ามีและนับได้ ขอฟีดในรูปแบบเดียวกับ A3 คือ `{ lotId, capacity, free, observedAt }`

**C2. ถ้ายังไม่มี เริ่มจากคนรายงานได้ไหม** ❌

- แอปมีกลไกให้คนกดรายงานอยู่แล้ว (ที่ใช้กับรถเมล์) ใช้กับลานจอดได้โดยไม่ต้องซื้ออะไร
- **ที่ขอ:** รายชื่อลานจอด + พิกัด + ความจุคร่าว ๆ + ใครใช้ได้ (นักศึกษา/บุคลากร/ผู้มาติดต่อ) เท่านี้เริ่มได้

## เราจะทำอะไรกับข้อมูล และจะไม่ทำอะไร

กฎพวกนี้เขียนไว้ในโค้ดแล้ว ไม่ใช่คำสัญญาลอย ๆ:

**จะทำ**

- **ทุกค่าแสดงพร้อมเวลาที่วัดและที่มา** ค่าที่เก่าถูกเขียนว่าเก่า ไม่ปลอมเป็นค่าสด — ตอนนี้โรงอาหารยอมให้ค่าเก่าไม่เกิน 10 นาที และคำตอบสดที่ค้างบนจอเกิน 2 นาทีเปลี่ยนข้อความเป็น *"เวลารอเมื่อ 11:55"* พร้อมปุ่มเช็กอีกครั้ง
- **ตัวเลขเป็นของเจ้าของระบบ ฝั่งเราไม่ประมาณเพิ่ม** ถ้าฟีดไม่ส่ง ETA มา เราไม่คำนวณให้
- **ฟีดเงียบ บอกว่าเงียบ** ไม่เติมค่าแทนเซนเซอร์ที่หาย ไม่แสดงศูนย์แทนค่าที่ไม่รู้
- **ลิงก์กลับหน้าของมหาวิทยาลัยเสมอ** สำหรับเรื่องที่เป็นของมหาวิทยาลัย เช่น การจองห้องและบริการต่าง ๆ เราเปิดหน้าของมหาวิทยาลัยเอง ไม่ทำหน้าซ้อน

**จะไม่ทำ**

- **ไม่อ่านตารางการจองที่พิมพ์ชื่อผู้จอง** ตัดสินใจไว้แล้วตอน #319 — หน้าจองห้องของมหาวิทยาลัยแสดงชื่อคนจอง เราจึงแค่ลิงก์ไป ไม่ดูดข้อมูล
- **ไม่เก็บ MAC address และไม่ทำ presence รายบุคคล** นับจำนวนคนได้ ตามตัวคนไม่ได้ ถ้าทำได้มันจะกลายเป็นเครื่องมือเช็กชื่อและเฝ้าดูพนักงานทันที
- **ไม่ขอและไม่เก็บรหัสนักศึกษา** ข้อมูลคณะและชั้นปีในแอปเป็นการกรอกเองโดยสมัครใจ ลบได้ หายไปพร้อมบัญชี และเจ้าภาพเห็นเป็นช่วงละ 5 คน แสดงเมื่อถึง 20 คนขึ้นไป คณะเล็กไม่ระบุชื่อ
- **ไม่ส่งต่อข้อมูลให้บุคคลที่สาม**

**ไม่ได้ขอ** รายชื่อนักศึกษาหรือบุคลากร · รหัสนักศึกษา · ตารางเรียนรายบุคคล · ภาพจากกล้องวงจรปิด · ข้อมูลการเงิน

## สิ่งที่เอกสารนี้ยังไม่ได้ตรวจสอบ

- ยังไม่ได้ติดต่อหน่วยงานใดของมหาวิทยาลัย เอกสารนี้คือสิ่งที่จะถาม ไม่ใช่สิ่งที่ได้คำตอบมาแล้ว
- ยังไม่รู้ว่าหน่วยไหนถือข้อมูลแต่ละชุด ชื่อหน่วยที่คาดไว้ (ฝ่ายยานพาหนะ กองอาคารสถานที่ สำนักวิทยบริการ) เป็นการเดาจากโครงสร้างมหาวิทยาลัยทั่วไป ยังไม่ได้ยืนยัน
- รูปแบบ JSON ในข้อ A3 คือรูปที่ฝั่งเรารับได้ ไม่ใช่รูปที่ฝั่งมหาวิทยาลัยมี ถ้าของเขาเป็นรูปอื่น เราแปลงฝั่งเราเอง — ไม่ต้องให้เขาแก้ระบบตาม
