## คำถามที่ 1 — "ยังไม่มีเจ้าบ้านจริงบนเกาะเลยใช่ไหม"

### คำตอบ

> **ใช่ครับ ตอนนี้เจ้าบ้านของ quest บนเกาะสีชังคือทีมเราเอง**
>
> และเราไม่ได้ซ่อนไว้ — ในฐานข้อมูล production เจ้าบ้านชื่อ
> **"ChivaGo team · Koh Sichang"** และ quest ทั้งสองอันมีคำว่า
> **"(ตัวอย่าง)"** ต่อท้ายชื่อ เปิดแอปดูตอนนี้ก็เห็น
> เราเขียนแบบนั้นตั้งแต่ก่อนรู้ว่าจะมีใครถาม
>
> เหตุผลที่ยังไม่มีเจ้าบ้านจริง ไม่ใช่เพราะระบบยังไม่พร้อม
> **ระบบพร้อมแล้ว ที่ยังไม่มีคือคนที่เซ็น** และสองอย่างนี้ต่างกัน
>
> สิ่งที่พร้อม: การเพิ่มพื้นที่ใหม่พร้อมเจ้าบ้านและคีย์ของเขา
> เป็นคำสั่งเดียว `seed-area.ts --area <พื้นที่>` ซึ่งสร้างเจ้าบ้าน
> ออกคีย์ให้แต่ละราย แล้วคืนคีย์มาครั้งเดียว — เก็บเป็น hash อ่านกลับไม่ได้
> วันที่ป้าร้านแรกตกลง เราไม่ต้องเขียนโค้ดเพิ่มเลยสักบรรทัด
>
> ใน roadmap ของเรา **ระยะ 1 (ก.พ.–ก.ย. 2570) ตั้งเป้า host ที่มีชื่อจริง 30 ราย
> และร้านพันธมิตร 50 แห่งที่จ่ายคอมมิชชัน** และประตูของระยะ 1 คือ
> **รายได้คอมมิชชันจ่ายค่าแพลตฟอร์มได้ทุกเดือน และผู้ตรวจสอบภายนอกยอมรับ statement**
> ถ้าไม่ผ่านประตู เราไม่ขยายไปพื้นที่ถัดไป — เขียนไว้ก่อนมางานนี้ ไม่ใช่เพิ่งตอบ

### ถ้าถามต่อ "แล้วจะรู้ได้ไงว่าเจ้าบ้านตรวจจริง ไม่ใช่กดผ่านหมด"

> เราวัด **อัตราการปฏิเสธหลักฐานรายเจ้าบ้าน** และถือว่า
> **อัตราที่ต่ำผิดปกติคือสัญญาณเตือน ไม่ใช่สัญญาณดี**
> เจ้าบ้านที่ผ่านทุกอันคือเจ้าบ้านที่อาจไม่ได้ดู
> บวกการกลั่นกรองสองชั้น และการตรวจจากภายนอกปีละครั้ง

### ตรวจข้ออ้างนี้ได้จาก

- ฐานข้อมูล production: `hosts.id = 'h-sichang-chivago'`, `name = 'ChivaGo team · Koh Sichang'`

- `apps/api/src/seed-area.ts` — สร้างเจ้าบ้าน + ออกคีย์ + ลงสถานที่ + ลง quest ในทรานแซกชันเดียว
- `packages/core/src/sichang.test.ts` — เทสที่บังคับว่า quest ตัวอย่างต้องเป็นของทีม และห้ามอ้างชื่อร้านจริง

## คำถามที่ 2 — "production มีเครื่องเดียว เครื่องตายแล้วจบเลยไหม"

### คำตอบ

> **เครื่องเดียวจริงครับ และถ้าเครื่องนั้นตาย ระบบล่มทั้งระบบ**
> เราเขียนข้อนี้ไว้ในตารางความเสี่ยงของเราเองว่า "ระดับสูง"
>
> แต่ขั้นที่สองไม่ใช่แผนบนกระดาษ — **มันรันอยู่ตอนนี้**
> แอป `chivago-ha` มีสองเครื่องในสิงคโปร์ ทั้งคู่สถานะ started
> ผ่าน health check ทั้งคู่ ใช้ LiteFS ทำสำเนาฐานข้อมูลระหว่างกัน
> กับ Consul lease เลือกตัวที่เขียนได้ ถ้าอยากลอง เปิด
> `chivago-ha.fly.dev/health` ได้เลยตอนนี้
>
> ขั้นที่สามคือ Cloudflare Durable Objects **ซึ่ง CI รันชุดเทส API
> ทั้งชุดซ้ำสองรอบทุกครั้ง** — รอบแรกผ่าน SQLite รอบสองผ่าน adapter
> ที่ปฏิเสธ SQL แบบเดียวกับที่ Cloudflare ปฏิเสธ
> แปลว่า SQL ที่จะพังตอนย้ายไป edge **พังใน CI วันนี้ ไม่ใช่หลัง deploy**
>
> **แล้วทำไมยังไม่เปิดขั้นสอง** เพราะบนผู้ใช้ระดับนี้ LiteFS มีแต่ต้นทุน
> ต้องรันเป็น root เพราะ FUSE ขอ CAP_SYS_ADMIN เพิ่ม hop เพิ่ม lease ที่ขัดกันได้
> แล้วไม่ได้อะไรกลับมาเลย **เราเลือกจะไม่จ่ายค่านั้นจนกว่าจะมีคนใช้จริง**
> นี่คือการตัดสินใจ ไม่ใช่งานที่ค้าง — และสวิตช์อยู่ตรงนั้น รอเปิด

### ถ้าถามต่อ "แล้วข้อมูลล่ะ กู้ได้ไหม"

> **ซ้อมกู้จริงเมื่อ 6 พ.ย. ก่อนมางานนี้ ผ่านครับ** —
> กู้ลงเครื่อง test ได้ครบ 63 ตาราง 5,516 แถว ตรงกับ production ทุกแถว
> ตรวจความถูกต้องผ่าน แล้วบูตแอปจริงทับไฟล์ที่กู้มาได้
>
> และเจอของที่ไม่รู้มาก่อนหนึ่งอย่าง: **บัญชี Fly ของเราสร้าง volume ใหม่
> จาก snapshot ไม่ได้ ติดโควตา** เส้นทางกู้คืนมาตรฐานของ Fly จึงยังใช้ไม่ได้
> เราเลยสำรองเป็นไฟล์เก็บไว้นอก Fly แทน ซึ่งทดสอบแล้วว่ากู้ได้
> — **ข้อนี้คือเหตุผลที่ต้องซ้อม ไม่ใช่อ่านเอกสารแล้วเชื่อว่าทำได้**

### ตรวจข้ออ้างนี้ได้จาก

- `fly machines list -a chivago-ha` → 2 เครื่อง สถานะ started ทั้งคู่ region sin
- `https://chivago-ha.fly.dev/health` → 200
- `fly.ha.toml`, `litefs.yml` ในรีโป
- `apps/api/src/do-storage.ts` และ `pnpm --filter @chivago/api test:durable`
- `docs/71-disaster-recovery-th.md` — ผลการซ้อมกู้คืนแบบละเอียด

## คำถามที่ 3 — "มีใครเซ็น MOU กับคุณแล้วบ้าง"

### คำตอบ

> **ยังไม่มีสักรายครับ** ที่อยู่ในสไลด์หน้าพันธมิตรทั้งหมด —
> เทศบาลตำบลเกาะสีชัง จุฬาฯ สายด่วน 1669 อบก. —
> **เป็นเป้าหมายความร่วมมือ ยังไม่มีใครเซ็น**
> เราเขียนบรรทัดนั้นกำกับไว้ในเอกสารของเราเองว่ายังไม่มีรายไหนเซ็น
>

> สิ่งที่เรามีให้คนเซ็นดูตอนนี้คือระบบที่เดินได้จริงบนเกาะของเขา
> เปิด chivargo.com เลือก KOH SICHANG จะเห็นสถานที่จริงห้าแห่ง
> ท่าล่าง โรงพยาบาล หาดถ้ำพัง พระจุฑาธุชราชฐาน และย่านร้านค้า

>
> ลำดับของเราคือ **เอาของไปให้ดูก่อน แล้วค่อยขอลายเซ็น**
> ไม่ใช่เอาลายเซ็นมาโชว์บนเวทีแล้วค่อยไปสร้างของ

> ในช่วงนั้นไม่ใช่หลักฐานการอยู่ในพื้นที่** เราเขียนเองในโค้ดตัวเอง
> ทั้งที่ไม่มีใครบังคับ และไม่มีใครจะรู้ถ้าเราไม่เขียน
>
> ทีมที่พองตัวเลขไม่เขียนย่อหน้าแบบนั้น

> ⚠️ **ยอด ฿757,332/ปี ที่เคยใช้ — เลิกใช้** ตัวเลขนั้นปรากฏในรีโปครั้งเดียว

> ❌ ~~"ลูกค้าองค์กร 6 ราย ที่ ฿150K ก็จ่ายค่าแพลตฟอร์มได้ทั้งหมด"~~

กรรมการกดเครื่องคิดเลขสิบวินาทีก็เจอว่าตัวเลขของเราขัดกันเอง

### quest flow ของเกาะสีชัง — เดินครบวงจรแล้ว บนข้อมูล production จริง

เดินผ่าน HTTP จริงทุกขั้น บนสำเนาฐานข้อมูล production ที่กู้มาเมื่อ 6 พ.ย.

| ขั้น | ผล |
|---|---|
| สมัครอุปกรณ์ `POST /devices` | ผ่าน ได้คีย์ 52 ตัวอักษร |
| `GET /quests` เห็น quest สีชัง | ผ่าน — `q-sc-beach`, `q-sc-dropoff` |
| รับภารกิจ `POST /quests/q-sc-beach/join` | ผ่าน stage = `joined` |
| **เช็กอินนอกรั้ว** (จากท่าเรือ ห่าง ~1.9 กม.) | **ปฏิเสธ 403 `OUTSIDE_GEOFENCE`** |
| **เช็กอินด้วย GPS ปลอม** (`mocked: true`) | **ปฏิเสธ 403 `MOCK_LOCATION`** |
| เช็กอินในรั้ว ที่หาดถ้ำพังจริง | ผ่าน stage = `arrived` |
| **ส่งหลักฐานทันทีไม่รอครบ 10 นาที** | **ปฏิเสธ 409 `TOO_SOON`** |
| ส่งหลักฐานหลังครบเวลา | ผ่าน stage = `host_verification` |
| เจ้าบ้านกดยืนยัน | ผ่าน stage = `complete` · ได้ **120 Green** |
| ออกใบรับรอง | ผ่าน `CG-2026-H9G5G4` + digest sha256 |
| เปิดหน้าตรวจใบรับรอง | ผ่าน 200 แสดงเลขที่ digest หาดถ้ำพัง และชื่อเจ้าบ้าน |
| เปิดด้วยเลขที่มั่ว | **404 ถูกต้อง** |

**สามบรรทัดที่เป็นตัวหนาคือของที่เอาขึ้นเวทีได้** เพราะมันคือการพิสูจน์ว่า
รั้วไม่ใช่คำพูด — ระบบปฏิเสธคนที่ไม่ได้อยู่ตรงนั้นจริง ๆ ต่อหน้ากรรมการได้

> ⚠️ **แต่เครื่องที่เคยเลือกไว้แล้วยังจำของเดิม** — ค่าที่เก็บไว้ชนะค่าเริ่มต้นเสมอ
> (ถูกต้องแล้ว เพราะเป็นสิ่งที่ผู้ใช้เลือกเอง) **วันแข่งให้เปิดด้วย URL นี้**
> `chivargo.com/?area=koh-sichang` ซึ่งตั้งพื้นที่ให้และจำไว้ด้วย ไม่ต้องกดเอง

และ `demo:reset` **มีเวอร์ชันของสีชังแล้ว**

```
pnpm --filter @chivago/api demo:reset --area koh-sichang --walk
```

ไม่ใส่ `--area` จะเป็นเกาะสมุยเหมือนเดิมทุกประการ (ตรวจแล้วว่าไม่พัง)

> ⚠️ **สีชังยังผ่านไม่ครบ 10 หน้าจอ — ติด Marketplace ฝั่ง green**
> ของรางวัลใน Marketplace ทั้ง 16 รายการเป็นร้านของเกาะสมุย **ไม่มีของสีชังเลย**
> และ quest สีชังสองอันให้รวม 180 green ขณะที่ของถูกสุดฝั่ง green ราคา 250
> **ไม่ได้แก้ด้วยการเพิ่มแต้มให้ตัวเอง** เพราะแต้มต้องมาจากงานที่ตรวจแล้วเท่านั้น
> และไม่ได้แก้ด้วยการแต่งร้านบนเกาะขึ้นมา เพราะนั่นคือการกุผู้ประกอบการที่มีตัวตนจริง
> → เป็นการตัดสินใจของเจ้าของงาน ดูข้อเสนอท้ายเอกสารนี้

### 2. ~~`/config` ขึ้นว่า `autoApprove: true`~~ → มีชื่อใหม่ที่อ่านแล้วเข้าใจถูกแล้ว

`/config` ตอนนี้คืน **`storiesAutoApprove`** เป็นชื่อหลัก และคง `autoApprove`
ไว้เป็น alias ที่ทำเครื่องหมาย deprecated (ไม่ลบ เพราะเป็น API สาธารณะ
แอปเวอร์ชันเก่าและ SDK ยังอ่านชื่อเดิมอยู่) ทั้งสองชื่อมีค่าเท่ากันเสมอ —
มีเทสบังคับไว้ว่าห้ามไม่ตรงกัน

ตรวจบนเซิร์ฟเวอร์ที่รันจริงแล้ว:

```json
{"fenceOff":false,"storiesAutoApprove":false,"autoApprove":false,"aiAssist":false}
```

**ถ้ายังโดนถาม ตอบแบบนี้:** "ฟิลด์นั้นคือเรื่องคลิปที่คนโพสต์ครับ ไม่ใช่หลักฐานภารกิจ
คลิปขึ้นทันทีแล้วเราซ่อนทีหลังได้ในคลิกเดียวและหมดอายุเองใน 7 วัน
ส่วนแต้ม Green ออกทางเดียวคือเจ้าบ้านกดยืนยัน"

> **ยังไม่ได้ deploy** การแก้ทั้งสองข้ออยู่ในเครื่องเท่านั้น
> `chivargo.com` จะยังเป็นของเดิมจนกว่าจะ deploy
