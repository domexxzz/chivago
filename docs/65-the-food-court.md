# 65 — The food court · สั่งล่วงหน้าที่โรงอาหารกลาง มทร.ธัญบุรี

ระยะที่ 1 ของการเอาระบบสั่งอาหารล่วงหน้าเข้ามาใน ChivaGo ทดลองที่ `rmutt-canteen`
(โรงอาหารกลาง, OSM way 547540111) ซึ่ง seed เขียนไว้แล้วว่า *"จุดเดียวในวิทยาเขตที่ทุกคนมาพร้อมกันในชั่วโมงเดียว"*
สถานะ: **มีโค้ดแล้ว 6 ต.ค. 2569 · ร้านในโรงอาหารยังไม่ได้เข้าร่วม ใช้ร้านตัวอย่างแทนไปก่อน**

ประโยคเดียว:

> **ChivaGo พาไปถึงร้าน สั่งก่อนรับออเดอร์** ChivaGo บอกว่าร้านไหนรับสั่งล่วงหน้าและต้องรอกี่นาที
> แล้วเปิดหน้าสั่งของร้านใน **สั่งก่อน** (sangkon.fly.dev) ส่วนเมนู การจ่ายเงิน และคิวในครัวเป็นของสั่งก่อนทั้งหมด

---

## ปัญหาที่แก้

ช่วงพักเที่ยงนักศึกษาออกจากห้องพร้อมกัน โรงอาหารจึงคิวยาวในชั่วโมงเดียว ร้านทำได้จำกัดต่อนาที
คนที่ไม่อยากยืนรอก็ไปที่อื่นหรือไม่กิน สั่งก่อนแก้ตรงนี้ด้วยการให้สั่งและจ่ายตั้งแต่ท้ายคาบ
แล้วนัดเวลารับตามความจุจริงของครัว ChivaGo มีนักศึกษาอยู่ในแคมปัสอยู่แล้ว จึงเป็นทางเข้าที่เป็นธรรมชาติ

## หลักที่ห้ามละเมิด

1. **ChivaGo ไม่รับออเดอร์และไม่แตะเงิน** ตรงกับที่ docs/01 เขียนไว้ว่า *No money movement*
   และ docs/63 ว่าไม่มีการจองหรือเก็บเงินผ่าน ChivaGo เงินวิ่งจากนักศึกษาเข้าพร้อมเพย์ของร้านโดยตรง
   การ์ดบอกในหน้าจอว่า *สั่งและจ่ายผ่านสั่งก่อน เงินเข้าร้านโดยตรง*
2. **เวลารอเป็นของร้าน ไม่ได้ประมาณฝั่งนี้** ตัวเลขมาจากคิวในครัวของแต่ละร้าน
   (สั่งก่อนคำนวณจากความจุครัวต่อช่วง 10 นาทีและออเดอร์ที่จองไว้) ChivaGo แค่อ่านมาแสดง
3. **ค่าที่ไม่สดต้องบอกว่าไม่สด** สั่งก่อนไม่ตอบ ก็ส่งค่าล่าสุดพร้อมเวลาที่อ่านได้ (`provenance: 'stale'`)
   ได้ไม่เกิน 10 นาที และการ์ดแสดงแค่ชื่อร้านกับปุ่ม *ดูเมนู* ไม่อ้างเวลารอหรือสถานะจากค่าเก่า
   (เวลารอ 5 นาทีเมื่อสิบนาทีก่อนตอนเที่ยงคือคำสัญญาที่ไม่มีใครให้) ไม่เคยรู้เลยหรือเก่ากว่านั้น
   ก็บอกว่าติดต่อร้านไม่ได้ ไม่สร้างร้านหรือเวลารอขึ้นมาเอง ส่วนตอบสดแต่ไม่มีร้าน บอกว่ายังไม่มีร้านรับสั่ง
4. **ร้านตัวอย่างต้องติดป้ายตัวอย่าง** ร้าน `demo` ของสั่งก่อนไม่ได้อยู่ในโรงอาหารนี้
   การ์ดเขียนว่า *ตัวอย่าง · ไม่ใช่ร้านในโรงอาหารนี้* ด้วยสีและตำแหน่งเดียวกับข้อเสนอตัวอย่างในตลาด
   ป้ายนี้ตัดสินฝั่งนี้ (`isExampleStall`) คำตอบเพิ่มป้ายให้ร้านอื่นได้ แต่เอาป้ายออกจากร้านตัวอย่างไม่ได้
5. **ลิงก์ที่กดไปต้องเป็นของบริการที่ตั้งค่าไว้** `orderUrl` สร้างฝั่งนี้จาก `CHIVAGO_SANGKON_URL` กับ slug
   ไม่เอาลิงก์ที่คำตอบส่งมา คำตอบที่ถูกแก้จึงพานักศึกษาไปเว็บอื่นไม่ได้ ค่าตั้งต้องเป็น https
   (หรือ http บนเครื่องตัวเองตอนพัฒนา) ไม่อย่างนั้นปิดการ์ดและเตือนครั้งเดียวตอนเริ่ม
   แอปตรวจลิงก์ซ้ำด้วย `isOrderLink` ก่อนแสดงปุ่ม
6. **อ่านเฉพาะที่ถาม** รับเฉพาะร้านที่อยู่ใน `PLACE_STALLS` ร้านละครั้ง เรียงตามที่ตั้งไว้
   คำตอบใหญ่เกิน 64 KB ถูกปฏิเสธโดยไม่อ่านต่อ ไม่ตาม redirect ชื่อร้านตัดอักขระควบคุมและเครื่องหมายกลับทิศข้อความ
   ตัดความยาวทีละตัวอักษรเต็ม (ไม่แยกวรรณยุกต์ออกจากพยัญชนะ) ตัวเลขที่อยู่นอกช่วงถือว่าไม่รู้ ไม่บีบให้อยู่ในช่วง

## ทำงานอย่างไร

```
แอป ──GET /places/rmutt-canteen/stalls──▶ ChivaGo API ──GET /api/shop-status?slugs=…──▶ สั่งก่อน
         (เฉพาะสถานที่ที่มีร้าน)              แคช 30 วิ · timeout 4 วิ · ขอพร้อมกันได้คำขอเดียว
                                              ไม่เกิน 64 KB · ไม่ตาม redirect · ล้มแล้วรอ 15 วิ
แอป ──กด "สั่งล่วงหน้า"──▶ เปิด https://sangkon.fly.dev/s/<slug> (หน้าสั่งของร้าน)
```

| ส่วน | ไฟล์ | ทำอะไร |
|---|---|---|
| ร้านต่อสถานที่ | `packages/core/src/stalls.ts` | `PLACE_STALLS` (แผนที่คงที่แบบ `SAFETY_PHRASES` ไม่ต้อง migration) อ่านผ่าน `stallSourceFor` (Object.hasOwn: `constructor` ไม่ใช่สถานที่), ชนิด `Stall` / `PlaceStalls`, `stallsFromShopStatus` แปลงคำตอบของสั่งก่อน (epoch ms → ISO, ทิ้งแถวที่รูปร่างผิด ร้านที่ไม่ได้ถาม และแถวซ้ำ, คืน `missing` กับจำนวนที่ทิ้ง), `stallState`, `isOrderLink`, `isExampleStall` |
| ตัดข้อความ | `packages/core/src/text.ts` | `graphemes` / `capText` ย้ายมาจาก `proof-assist.ts` เพื่อใช้ร่วมกัน |
| ดึงจากสั่งก่อน | `apps/api/src/stalls.ts` | `getStalls` ไม่เคย throw, แคชในหน่วยความจำ 30 วินาที (ค่ารอมีค่าครึ่งนาที ไม่ใช่บันทึกของใคร และ replica ของ LiteFS เขียนไม่ได้), ล้มแล้วรอ 15 วินาทีก่อนถามใหม่, ค่าเก่าเสิร์ฟได้ไม่เกิน 10 นาที, คำตอบที่เปลี่ยนรูปร่าง (มีแถวแต่อ่านไม่ได้สักแถว) ถือว่าล้มและเก็บค่าดีล่าสุดไว้, `sangkonBase` ตรวจค่าตั้ง |
| เส้นทาง | `apps/api/src/server.ts` | `GET /places/:id/stalls` อยู่หลัง middleware ยืนยันตัวตนเหมือน `/places/:id/history` (ไม่มีกุญแจเครื่อง = 401) แยกจาก `/places/:id` เพราะ place ถูกให้คะแนนให้แผนที่ ตัววางแผน และมอนสเตอร์ ซึ่งไม่ควรรอคิวครัว |
| การ์ดในแอป | `apps/mobile/src/components/Stalls.tsx` | อยู่ใต้ "ตอนนี้ที่นี่" ในหน้าสถานที่ ขอข้อมูลเฉพาะสถานที่ที่มีใน `PLACE_STALLS` สถานที่อื่นจึงไม่มีคำขอเพิ่ม (เทสต์หน้าเฉวงที่ล็อกคำขอ 8 รายการยังผ่าน) |
| คำในแอป | `packages/core/src/strings.ts` → `place.stall*` | สองภาษา ใช้ `${…}` ชุดเดียวกันทั้งไทยและอังกฤษ |

สถานะของร้านแต่ละร้าน (`stallState`) เมื่อข้อมูลสด: **ปิด** (บอกเวลาเปิดครั้งถัดไปตามนาฬิกาไทย: วันนี้บอกแค่เวลา
พรุ่งนี้บอกว่า *เปิดพรุ่งนี้* ไกลกว่านั้นบอกวันที่) → **ไม่รับสั่งล่วงหน้าตอนนี้** (ร้านปิดสวิตช์) → **ยังไม่พร้อมรับเงิน**
→ **ตอนนี้ไม่มีเวลารับที่ว่าง** (เปิดและรับสั่ง แต่สั่งก่อนให้ `waitMin: null` เพราะครัวเต็มหรือใกล้ปิดจนทำไม่ทัน)
→ **สั่งได้** (แสดง *รอประมาณ N นาที*) ทุกสถานะที่สั่งไม่ได้ยังกด *ดูเมนู* ได้

## เดโมแบบ static

เดโมบน Vercel ตอบจาก snapshot แต่ `/places/:id/stalls` **ตอบสดในเซิร์ฟเวอร์เดโม** (`src/demo/stalls.ts`)
แทนการ capture เพราะเวลารอที่ capture ไว้จะถูกเล่นซ้ำเหมือนเป็นตอนนี้ เดโมจึงแสดงชื่อร้านโดยไม่อ้างสถานะ
(*ที่นี่ไม่ได้อ่านสถานะสดของร้าน ดูได้ในหน้าของแต่ละร้าน*) และปุ่มเปิดสั่งก่อนตัวจริง
ซึ่งเป็นสิ่งเดียวที่ build แบบ static ให้ได้อย่างตรงไปตรงมา

## เพิ่มร้านจริง

1. ร้านสมัครในสั่งก่อน (`pnpm shop:create` ใน repo sangkon) ได้ slug และ PIN ส่วนเมนูกับพร้อมเพย์ร้านกรอกเองในหน้าตั้งค่า
2. ใส่ slug ใน `PLACE_STALLS['rmutt-canteen'].slugs` ตามลำดับที่อยากให้แสดง แล้วเอา `demo` ออกเมื่อมีร้านจริงร้านแรก
3. ใส่ชื่อร้านใน `DEMO_STALL_NAMES` (`apps/mobile/src/demo/stalls.ts`) ไม่อย่างนั้นเดโมแสดง slug แทนชื่อ
4. เทสต์ตรวจว่าทุกสถานที่ที่มีร้านเป็นสถานที่หมวด Food ที่มีใน seed ทุก slug อยู่ในรูปแบบที่สั่งก่อนใช้และไม่ซ้ำ
   และทุกร้านในเดโมมีชื่อ ร้านที่ตั้งไว้แต่สั่งก่อนไม่มี จะถูกเตือนใน log ครั้งเดียวเมื่อรายการเปลี่ยน

## ยังไม่ได้ทำ (ระยะที่ 2)

- ออเดอร์ผูกกับบัญชี ChivaGo และมีประวัติการสั่งในแอป
- แจ้ง "อาหารพร้อม" ผ่าน push ของ ChivaGo แทน LINE ซึ่งไม่ติดโควตา 300 ข้อความต่อเดือนของ LINE OA
- แต้มเมื่อรับอาหารแล้ว ร้านเป็นคนกด "ลูกค้ารับแล้ว" จึงเป็นเหตุการณ์ที่มีคนยืนยัน ตรงกับหลัก *แต้มจะมีค่าก็ต่อเมื่อมีคนตรวจ*
- endpoint นี้ยังไม่อยู่ใน contract (`contract/*.json`) เพราะ SDK ไม่ได้อ่าน ตามแบบของ `/listings` และ `/transit`
- สั่งหลายร้านในครั้งเดียว ตอนนี้แยกเป็นคนละออเดอร์ คนละการจ่าย
